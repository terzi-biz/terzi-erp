# Фінанси, плани продажів, задачі, інтеграції — план по хвилях

Обсяг великий, тому робимо 5 хвиль. Кожна хвиля — окремий крок із перевіркою, публікація тільки з вашого дозволу.

## Хвиля 1 — Вкладка «Фінанси» (редизайн + звіти)
- Новий «Огляд»: графік по місяцях (надходження / витрати / прибуток / EBITDA), KPI-картки з клікабельною розшифровкою, план vs факт по статтях.
- Звіти з фільтром періоду (місяць / квартал / довільно), дата = дата проведення операції в Finmap (Київ, тільки фактичні, без видалених):
  - «Прибуток по місяцях» — таблиця + графік, маржа, % ФОП адміністративного / виробничого.
  - «Контрагенти» — обороти, борги, топ за витратами/доходами, перехід до операцій.
  - «Витрати» — по статтях і підстаттях, динаміка по місяцях, частка від доходу.
- Власні метрики: формула з готових показників (напр. «Реклама / Дохід, %»), зберігається в налаштуваннях, показується карткою.

## Хвиля 2 — «Плани продажів» + «План vs факт» на дашборді
- Розширюємо існуючий план продажів: цілі на місяць по менеджерах і по прорабах (сума договорів, к-сть угод, для прорабів — виконані роботи).
- Блок на дашборді «Планування vs факт»: прогрес по кожній людині, % виконання, прогноз на кінець місяця.

## Хвиля 3 — Задачі (уніфікований паспорт)
- Поля: автор (хто поставив), відповідальний, співвиконавці, тип, пріоритет, дедлайн, нагадування, етап/статус, прив'язка до ліда / заміру / замовлення / клієнта, коментарі.
- Уведомлення в ERP: дзвіночок у боковій панелі з лічильником, блок «Мої задачі» на дашборді, нагадування за N хв до дедлайну, повідомлення «вам поставили задачу від …».
- Telegram-нагадування — після підключення бота у Хвилі 4.

## Хвиля 4 — Налаштування інтеграцій (автономне підключення)
- Кожна інтеграція отримує форму: поля для ключів / секретів / ID акаунта, кнопки «Зберегти», «Перевірити», «Синхронізувати», «Від'єднати», журнал. Ключі зберігаються тільки на сервері, у браузер не повертаються (показується лише «•••• збережено»).
- Статус «Підключено» тільки після реального успішного запиту до сервісу.
- Вхід через акаунт (OAuth): Meta (Facebook / Instagram / Meta Ads), TikTok Ads, Google (Ads / GA4) — кнопка «Увійти через …». Для цього потрібна одноразова реєстрація застосунку у кабінеті розробника кожного сервісу (я дам покрокову інструкцію, ви вставите Client ID / Secret у ту ж форму).
- Де OAuth неможливий — вебхук-адреса з кнопкою «Скопіювати» + секрет підпису (OLX, Telegram, Viber, WhatsApp, сайти/лендинги).

## Хвиля 5 — Відмова від keyCRM
- Повний повторний імпорт за вересень: запускаю з сервера, показую звіт — скільки з 60 вересневих замовлень отримали суму з кошторису, скільки лишились без суми і чому.
- Автоприв'язка суми замовлення з останнього збереженого кошторису (тільки де сума = 0, ручні суми не перетираються, з позначкою походження «Кошторис»).
- Жовтень — паралельна робота: щоденна звірка ERP vs keyCRM (нові ліди, замовлення, оплати) з переліком розбіжностей. З листопада — синхронізацію вимикаємо, дані лишаються.

## Технічні деталі
- Фінанси: агрегація на сервері (`createServerFn`) по `finance_transactions` з фільтрами `state` фактичний/не `deleted_in_finmap`; власні метрики — у `config_entries` (версійно), без нових таблиць.
- Плани: розширення `sales_plan_managers` полем ролі (manager/foreman) — additive міграція.
- Задачі: розширення `crm_tasks` (author_id, co_assignee_ids, remind_at, entity links) + нова таблиця `notifications` з RLS «тільки свої» + GRANT.
- Інтеграції: секрети в існуючій `integration_secrets` (доступ тільки service_role), OAuth через існуючі `integration_oauth_states` + `/api/public/integrations/oauth.callback`.
- Розрахунки детерміновані, формули Calculation Core не змінюються.

Почну з Хвилі 1, якщо не скажете інакше.

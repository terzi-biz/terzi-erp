# Склад, Фінанси та перейменування «Об'єкти» → «Замовлення»

Три пов'язані частини: перейменування центральної сутності, новий модуль «Склад», новий модуль «Фінанси». Все вбудовується в наявну ERP (кошториси, виробництво, календар, CRM, каталоги, RBAC, аудит).

## Частина 1. Об'єкти → Замовлення

- В UI всюди «Замовлення» / «Замовлення №», сайдбар, заголовки, PDF, повідомлення.
- Нові адреси: `/orders`, `/orders/new`, `/orders/$id`. Старі `/objects/*` залишаються як постійні редиректи, щоб збережені посилання працювали.
- У базі: `objects` → `orders`, дочірні таблиці `object_*` → `order_*`, колонки `object_id` → `order_id`, тригери/функції/RLS-політики оновлюються синхронно однією міграцією. Номер лишається у форматі `TRZ-РІК-NNNN` — історичні номери не змінюються.
- Модуль прав `objects` перейменовується на `orders` зі збереженням уже виданих прав.
- Дані не видаляються: це перейменування, не перестворення.

## Частина 2. Склад

Розділ `/warehouse` з вкладками:

1. **Номенклатура та залишки** — позиції складу зв'язані з каталогом матеріалів (стяжка/ПВХ/руберойд/утеплення/демонтаж), од. виміру, поточний залишок по кожному складу, мінімальний запас, підсвітка дефіциту.
2. **Склади** — довідник локацій (основний склад, авто/бригада, об'єкт), відповідальний.
3. **Рух товару** — документи: прихід (закупівля з постачальника), видача на замовлення, повернення з замовлення, списання, переміщення між складами. Кожен документ має номер, дату, автора, статус (чернетка / проведено), позиції, коментар. Проведення документа змінює залишки; скасування — сторнує.
4. **Резерв під замовлення** — з кошторису замовлення формується заявка на матеріали; резерв зменшує доступний залишок, видача списує резерв, показ дефіциту «треба закупити».
5. **Інвентаризація** — акт перерахунку по складу: облікова vs фактична кількість, розбіжність, автоматичний коригуючий рух після затвердження.
6. **Собівартість** — партійний облік із середньозваженою ціною: прихід оновлює середню ціну позиції, видача списує за середньою. Ціни закупівлі бачать лише ролі з правом на витрати.

Зв'язки з системою: картка замовлення отримує вкладку «Матеріали/Склад» (потреба з кошторису, зарезервовано, видано, залишок, дефіцит); екран «Виробництво» показує готовність матеріалів; списання зі складу автоматично створює фактичну витрату у Фінансах.

## Частина 3. Фінанси

Розділ `/finance` з вкладками:

1. **Рахунки й оплати** — рахунок формується з кошторису замовлення (аванс, поетапні, фінальний), статуси (виставлено / частково / оплачено / прострочено), оплати клієнтів, борг. Синхронізує фінансовий статус замовлення.
2. **Витрати** — закупівлі, зарплата/ФОП бригад, логістика, обладнання, загальні. Кожна витрата може бути прив'язана до замовлення або бути накладною.
3. **Каса та рахунки компанії** — довідник рахунків (готівка, безготівка, ФОП), рух коштів, залишки, простий cash-flow за період.
4. **P&L по замовленню** — план (кошторис) vs факт (оплати, витрати, склад): виторг, собівартість, маржа, прибуток, відхилення. Зведений звіт по всіх замовленнях, менеджерах, напрямках.

Зв'язки: картка замовлення отримує вкладку «Фінанси» (рахунки, оплати, витрати, P&L); дашборд і «Звіти» використовують фактичні дані замість лише кошторисних.

## Права доступу

Все через наявний модуль «Доступи»: модулі `warehouse`, `payments`, `expenses`, `finance` (вже є в довіднику) + новий `orders`. Ролі налаштовуються гнучко; за замовчуванням:
- Власник/Директор/Фінансист — повний доступ до Фінансів;
- Комірник/Виробництво — Склад повністю, без сум закупівлі;
- Менеджер — перегляд залишків і резерву по своїх замовленнях, без собівартості.
RLS на кожній новій таблиці, чутливі колонки (ціна закупівлі, маржа) закриті окремо. Усі проведення, скасування, оплати й інвентаризації пишуться в журнал аудиту.

## Технічні деталі

- Міграція перейменування: `ALTER TABLE ... RENAME`, оновлення функцій `set_object_number`, `log_object_status_change`, `sync_object_manager_assignment`, `private.can_view_object`/`can_manage_object` та всіх політик; переіндексація не потрібна.
- Нові таблиці: `warehouses`, `stock_items`, `stock_balances`, `stock_documents`, `stock_document_lines`, `stock_reservations`, `stock_counts`, `stock_count_lines`, `finance_accounts`, `invoices`, `invoice_lines`, `payments`, `expenses`. Для кожної — GRANT + RLS + політики за ролями/scope.
- Залишки рахуються з проведених рухів (детермінований перерахунок), кеш-таблиця балансів оновлюється тригером — жодних розрахунків на клієнті.
- Серверна логіка — `createServerFn` у `src/lib/warehouse.functions.ts` і `src/lib/finance.functions.ts`, чиста математика в `src/lib/warehouse-calc.ts` / `src/lib/finance-calc.ts` (покрито тестами). Грошові суми — цілі копійки, округлення лише на виводі.
- UI у стилі TERZI, українською, UAH, DD.MM.YYYY, адаптив під планшет/телефон.

## Порядок робіт

1. Перейменування Об'єкти → Замовлення (БД + маршрути + UI + редиректи).
2. Склад: схема, залишки, рух товару, UI.
3. Склад: резерв під замовлення, інвентаризація, собівартість, інтеграція з виробництвом.
4. Фінанси: рахунки, оплати, витрати, каса.
5. Фінанси: P&L по замовленню, зведені звіти, дашборд.
6. Права, RLS, аудит, тести, перевірка на мобільному.

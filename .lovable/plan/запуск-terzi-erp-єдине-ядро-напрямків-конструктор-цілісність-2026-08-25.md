## Хвиля 1 — Цілісність даних (без змін даних)

- Dry-run звіти окремою сторінкою «Аудит даних»: дублі клієнтів за нормалізованим телефоном, звінки → ліди за `phone_norm`, ліди → клієнти/замовлення, каталог без коду / з нульовою ціною, кошториси без версії прайсу.
- Кожен звіт: перелік записів, що будуть змінені, кнопка «Експорт», і **окрема** кнопка застосування з підтвердженням (по одному запису або пакетом). Жодного авто-мерджу.
- `price_history`: тригер на `catalog_items`, який пише кожну зміну ціни у версійовану історію. Історичні ціни не переписуються.
- Кошториси: заповнювати колонки `price_book_version` / `engine_version` при збереженні (у JSON вони вже є).

## Хвиля 2 — Єдиний runtime напрямків

- `src/lib/directions/runtime.ts` — один рушій: вхід (поля) → нормативи → матеріали / роботи / логістика / обладнання / амортизація → округлення й закупочна кратність → собівартість → клієнтська ціна → мінімальний чек, знижки, надбавки, податки, комісія → рядки кошторису.
- Кожен напрям = конфіг (JSONB, версійований), а не окремий калькулятор. Пʼять наявних модулів (стяжка, ПВХ, руберойд, утеплення, демонтаж) залишаються на своїх маршрутах і поетапно перемикаються на runtime через feature-флаг; збережені кошториси відкриваються старим шляхом за `engine_version`.
- Утеплення й демонтаж отримують режим «додатковий блок» — можуть входити в кошторис стяжки або покрівлі без задвоєння робіт, логістики, підйому й накладних.

## Хвиля 3 — Конструктор напрямків (адмін)

Розширення `/directions-editor` до повного конструктора без коду:

- Картка напрямку: назва, slug, опис, іконка, активність, порядок, ролі, тип послуги, самостійний / додатковий.
- Поля: число, площа, обʼєм, довжина, товщина, кількість, список, перемикач, текст, адреса, відстань, поверх, коефіцієнт, власне поле; обовʼязковість, min/max, одиниця, дефолт, підказка, видимість, залежність від інших полів.
- Привʼязка довідників: матеріали, роботи, логістика, обладнання, розхідники, додаткові послуги.
- Формули: кількість, закупка, продаж, собівартість, прибуток, маржа, ціна за м²/м³/м.п., кратність, мінімальний чек, попередження. Whitelist: `+ − × ÷`, `min`, `max`, `ceil`, `floor`, `round`, умовні вирази, посилання на поля й довідники, таблиці діапазонів, коефіцієнти, правила фасовки. Без eval, без генерації JS, без AI у підсумкових числах.
- Версії: чернетка → предпросмотр → тестовий розрахунок → публікація → порівняння версій, відкат, журнал змін. Опублікована версія незмінна.

## Хвиля 4 — CRM + keyCRM + Binotel як одна система

- Звінок → лід → клієнт → замовлення → замер → кошторис → рахунок: єдиний ланцюг звʼязків, матчинг за нормалізованим телефоном із підтвердженням для неоднозначних випадків.
- Вхідні ліди з Google Ads, Meta, TikTok, сайту: публічний endpoint `/api/public/leads/intake` з підписом і rate-limit, збереження UTM/gclid/fbclid, атрибуція джерела, дедуплікація.
- Webhooks: підпис, idempotency, retry-черга, журнал (ядро інтеграцій уже є — доповнюємо покриття й маскування PII в логах).

## Хвиля 5 — Аналітика, права, тести

- Маркетинг і фінанси: замість «0» — явні стани «немає даних за період» і чесні джерела цифр.
- Права: внутрішня собівартість, закупочні ціни, маржа й прибуток — тільки для дозволених ролей, фільтрація на сервері (перевіримо всі калькулятори й дашборди).
- Vitest: покриття runtime напрямків, формул, кратності, мінімального чеку, матчингу телефонів, дедуплікації лідів. TypeScript + build + тести після кожної хвилі, окремий commit на хвилю.

## Технічні деталі

- Нові таблиці: `direction_versions` (незмінні опубліковані конфіги), `direction_field_defs`, `direction_formula_defs`, `data_audit_runs` (dry-run звіти), `lead_intake_events`. Усі з GRANT + RLS: адмін/директор пишуть, решта читає за роллю.
- Секрети — тільки environment secrets / існуючий безпечний механізм; ключі не потрапляють у frontend і в звичайні таблиці.
- Міграції зворотні (кожна з `-- down` блоком у `docs/migrations/`), спочатку перевірка без застосування.
- Публікації не буде без окремого підтвердження директора.

## Порядок здачі

Хвиля 1 → 2 → 3 → 4 → 5, після кожної — звіт: що змінено, міграції, тести, блокери. Почати пропоную з Хвилі 1 (аудит і цілісність), бо на її результатах будуються звʼязки CRM у Хвилі 4.

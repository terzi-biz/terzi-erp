# CRM.md

## Поверхні

| Маршрут | Призначення |
| --- | --- |
| `/crm` | панель: KPI воронки, задачі дня, останні події |
| `/crm/requests` | звернення (сирий вхід) |
| `/crm/leads` | канбан лідів по стадіях воронки |
| `/crm/intake` | вхідні ліди з форм і рекламних джерел |
| `/crm/contacts` | контакти (E.164) |
| `/crm/calls` | дзвінки та повідомлення, прослуховування записів |

| `/clients`, `/clients/$id` | реєстр клієнтів і картка з 7 вкладками |

## Воронка

`crm_pipelines` → `crm_stages` → `crm_leads` (статуси `open`, `won`, `lost`,
`postponed`). Перехід стадії фіксується в `crm_lead_activities`.

## Ідентичність

Телефон нормалізується до E.164 (`src/lib/phone.ts`, тригер `crm_normalize_phone`).
`src/lib/crm/identity.ts` резолвить дзвінок/лід у контакт → клієнта → замовлення.
Пріоритет матчингу: явний `client_id` → `phone_norm` → email → ручне зв'язування.

## Уніфікована стрічка

`src/components/crm/UnifiedTimeline.tsx` зводить події з дзвінків, звернень,
лідів, задач, кошторисів, замовлень і платежів у єдину хронологію з фільтрами
за типом. Записи дзвінків Binotel підвантажуються за запитом.

## Картка клієнта

Вкладки: огляд, замовлення, кошториси, фінанси (рахунки/платежі/борг),
комунікації, задачі, файли/нотатки. KPI: сумарна виручка, борг, кількість
замовлень, остання активність, менеджер, джерело.

## Правила

- Лід без телефону й email не конвертується в клієнта.
- Дублікати клієнтів визначаються за `phone_norm`; злиття — ручне з аудитом.
- Менеджер бачить свої записи; ширший доступ — за роллю.
- Жодна CRM-синхронізація не перетирає ручні поля замовлення.

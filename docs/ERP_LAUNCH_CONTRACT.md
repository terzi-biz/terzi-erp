# TERZI ERP — Launch Contract v1.0 (Build Wave A)

Дата фіксації: 28.08.2026. Джерело: рішення директора (Plan Mode, хвиля A).
Код-константа контракту: `CONTRACT_VERSION = "terzi-contract@1.0"` (`src/lib/core/contract.ts`).
Усі розрахунки й тести посилаються на цей документ і на цю константу.

## 1. Контрольний сценарій стяжки М200 (100 м² × 7 см)

| Показник | Значення |
|---|---|
| Об'єм суміші | 7 м³ |
| Цемент М500 | 60 мішків × 25 кг |
| Пісок | 13,4 т — технічна потреба |
| Закупівля піску | окремо, дозволено округлення вгору (14 т) |
| Пластифікатор | 10 л |
| Фібра Sika 600 г | 8 упаковок |
| Дизель | 17 л у базовому сценарії |
| Поверховість | додаткові витрати рахуються окремою позицією, базові 17 л не змінюють |

## 2. Матриця фібри (упаковок на контрольні 7 м³)

М100 = 4, М150 = 6, М200 = 8, М250 = 10, М300 = 12.
Норми М200 = 9 і М200 = 11 у runtime заборонені.

## 3. Незмінність кошторисів

Збережений кошторис — immutable snapshot. Зміна прайсу, норм, податків чи обладнання
ніколи не перераховує збережений кошторис. Автоматичний backfill заборонений.

## 4. Податки

Матеріали — з ПДВ. Роботи й логістика — без ПДВ. Підсумок містить ПДВ лише в частині
матеріалів. Подвійне нарахування ПДВ заборонене: вхідний ПДВ постачальника для
неплатника входить у закупівельну собівартість і клієнту повторно не нараховується.
Клієнтський кошторис завжди явно показує податковий статус.

### 4.1 Профілі продавця та оплата

| Профіль | ПДВ | Безготівкова надбавка |
| --- | --- | --- |
| ФОП 2 | ні | 0% |
| ФОП 3 | ні | +6% (редагована) |
| Платник ПДВ | 20%, окремо по категоріях (матеріали, роботи, логістика, обладнання, послуги) | 0% |

Ставка застосовується рівно один раз до НЕТТО кожного рядка (`src/lib/core/index.ts`),
тому подвійне нарахування неможливе. Для неплатника всі категорійні галочки вимкнені.

### 4.2 Порядок комерційних коригувань

Фіксований і однаковий для всіх напрямків (`src/lib/core/adjustments.ts`):
складність % → знижка % → комісія партнера → безготівкова надбавка → добір до
мінімального чека. Податки в базу коригувань не входять.

### 4.3 Обладнання та амортизація

Галочки «враховувати в собівартості» (default ON) і «включати в клієнтську ціну»
(default OFF). Режими клієнтського відображення: окремий рядок, % від робіт,
% від робіт+логістики, % від нетто, грн/м², фіксована сума, включено в роботи.
База клієнтської амортизації ніколи не містить податків і самої амортизації.

## 5. Sikaplan D-15

Окрема неармована мембрана, окремий код `pvc_d15_detail`, лише вузли, проходки й
примикання. Заборонено використовувати замість основного армованого полотна 1,8 мм.
Діюча підтверджена ціна — 655 грн/м², якщо в довіднику немає пізнішої підтвердженої зміни.

### 5.1 Комплектація ПВХ

Армоване польове полотно 1,5 / 1,8 мм окремими кодами, рулон 2×20 м, кількість
рулонів, технічна та закупівельна площа й залишок. Профілі, планки, уголки,
капельники та накривки парапету закуповуються елементами по 2 м. Окремо:
телескопічні кріплення, рондоль, дюбель, шуруп, герметик, воронки d75/110/160,
аератори та точки обпайки.

## 6. Розрахункові й закупівельні кількості

Для ПВХ і руберойду завжди показуються роздільно: чиста кількість, технічна
(розрахункова) кількість, закупівельна кількість у заводській фасовці й залишок.
Вартість рахується по технічній кількості, закупівля — довідкова.

## 7. Клієнтський контур

У клієнтський API, PDF та інтерфейс ніколи не потрапляють: закупівельні ціни,
собівартість, внутрішня амортизація, прибуток, маржинальність, внутрішні коментарі,
секрети. Ключі відсутні фізично, а не зі значенням `null`.

## 8. Production-дані

Заборонено видаляти або об'єднувати production-дані без окремого підтвердження.
Замість видалення — deprecate, redirect або archive.

## 9. Маржинальність

`margin% = (виручка без клієнтських податків − повна собівартість) / виручка без
клієнтських податків × 100`. При нульовій виручці — «Не розраховується».
Амортизація не нараховується рекурсивно і не нараховується на податки.

## 10. Нульова ціна в довіднику

Нуль може бути законним. Статуси ціни: `missing`, `unconfirmed`, `confirmed`,
`confirmed_zero`. Blocking error виникає лише для відсутньої/непідтвердженої
обов'язкової ціни, недозволеного нуля, відсутнього обов'язкового коду або окремої
продаваної позиції без ціни. Випадкові fallback заборонені.

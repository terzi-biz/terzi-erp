# TESTING.md

## Рівні

| Рівень | Інструмент | Команда | Обсяг |
| --- | --- | --- | --- |
| Юніт / доменні | Vitest | `npm run test` | розрахунки, Core, price policy, ідентичність, план/факт |
| Типи | tsc | `npm run typecheck` | весь `src` |
| Лінт | ESLint | `npm run lint` | весь `src` |
| E2E smoke | Playwright | `npm run test:e2e` | усі маршрути: без 404, без 5xx, без console error |
| Міграції | node-скрипт | `npm run db:validate` | GRANT, RLS, політики, іменування |

## Обов'язкове покриття

1. **Розрахунки:** стяжка (M100–M300), ПВХ, руберойд, утеплення, демонтаж —
   контрольні числові кейси; фібра для 7 м³: M100=4, M150=6, M200=8, M250=10, M300=12.
2. **Calculation Core:** ПДВ один раз до нетто, амортизація, коригування,
   маржа/націнка, blocking errors при нульовій ціні.
3. **Незмінність кошторису:** зміна каталогу не змінює збережений кошторис.
4. **Реєстр модулів:** відсутність fallback на `screed`, збіг навігації й реєстру.
5. **Ідентичність:** нормалізація телефону в E.164, матчинг дзвінок → клієнт.
6. **Замовлення:** план/факт, P&L, збереження ручних полів при синхронізації.
7. **Склад/фінанси:** проведення документа, резерв, `sync_invoice_paid`.
8. **Інтеграції:** ідемпотентність `claim_integration_event`, replay-захист.
9. **Доступ:** клієнтський DTO/PDF не містить собівартості й маржі.

## Правила

- Кожна зміна доменної логіки супроводжується тестом.
- Кожен новий маршрут додається у список `e2e/smoke.spec.ts`.
- Тест не залежить від production-даних; використовується синтетичний seed.
- Червоні critical-перевірки блокують merge.

## Локально

```bash
npm run test -- --watch
npm run test:e2e -- --headed
```

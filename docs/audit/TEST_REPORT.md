### 2.1 Typecheck — 3 помилки (усі одного класу)

```
src/components/AppShell.tsx(157,20): TS2741 Property 'search' is missing ... to: "/demolition"|"/insulation"|"/roofing"|"/screed"
src/routes/clients.tsx(178,18):     TS2741 Property 'search' is missing ... to: "/screed"
src/routes/index.tsx(59,10):        TS2741 TS2741 Property 'search' is missing ... to: "/screed"
```

Причина: маршрути калькуляторів оголошують обов'язкові search-параметри (`Route.useSearch`), але `<Link to="/screed">` у навігації, на дашборді та в картці клієнта не передає `search`. Тобто **основні переходи на калькулятори типізовано некоректні**. Збірка це не ловить (Vite не робить typecheck), тому помилка дійшла до runtime-рівня.

Важливо: `bun run build` завершується успішно попри 3 помилки типів і 8686 помилок лінта. Тобто «збирається» тут **не є** ознакою якості.

### 2.2 Lint — 8701 проблем

Переважна більшість — `prettier/prettier` (форматування). Змістовні категорії, що залишаються:
- `@typescript-eslint/no-explicit-any` — сотні входжень, зокрема в серверних функціях і адаптерах інтеграцій; типізація даних із БД фактично відсутня;
- `react-hooks/rules-of-hooks` — `Route.useSearch` викликається у функції `component`, яку ESLint не розпізнає як React-компонент (мінімум 4 входження);
- решта — стиль.

Лінт у поточному стані **непридатний як gate**: 8686 помилок означає, що його ніколи не проганяли в CI, і нові реальні помилки в ньому потонуть.

## 4. Перевірка анонімного доступу (фактичний тест)

Виконано 18 read-only HTTP-запитів до PostgREST з publishable-ключем **без токена користувача**:

```
GET /rest/v1/{clients,estimates,profiles,crm_leads,objects,catalog_items,material_items,
              work_items,user_roles,access_roles,role_permissions,integrations,
              integration_secrets,audit_logs,coefficients,directions,crm_stages,
              registration_approvals}?select=*&limit=2
```

Результат: **усі 18 повернули HTTP 200 з порожнім масивом `[]`**.
Висновок: витоку даних анонімам немає — RLS відпрацьовує fail-closed. Водночас `anon` має GRANT SELECT на ці таблиці, тому факт існування таблиці та її назва розкриваються (рівень LOW).

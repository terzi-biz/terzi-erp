# BI.md — аналітичний шар

## Підхід

BI не переписує ERP-логіку. Показники або рахуються детермінованим кодом
(`src/lib/**`), або читаються read-only з Postgres зовнішнім інструментом.

## Внутрішні звіти

`/reports` — продажі та виробництво; `/finance` — гроші й борги;
`/marketing/analytics` — рекламні KPI; `/data-audit` — якість даних.

## Зовнішній BI (опційно)

Metabase (AGPL, окремий сервіс) підключається read-only користувачем:

```sql
CREATE ROLE bi_reader LOGIN PASSWORD '<з secret store>';
GRANT USAGE ON SCHEMA public TO bi_reader;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO bi_reader;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT ON TABLES TO bi_reader;
```

Роль не має INSERT/UPDATE/DELETE і не використовується застосунком.
Дашборди з internal-фінансами доступні лише керівництву й фінансам.

## Базові показники

| Показник | Формула |
| --- | --- |
| Виручка проєкту | затверджений кошторис / сума договору |
| Собівартість | матеріали + роботи + логістика + обладнання + інше |
| Прибуток | Виручка − Собівартість |
| Маржа | Прибуток / Виручка × 100 |
| Борг | Виставлено − Оплачено |
| CPL | витрати каналу / кількість лідів |
| CAC | витрати каналу / кількість клієнтів |
| ROMI | (виручка з каналу − витрати) / витрати × 100 |
| Конверсія стадії | перейшли далі / увійшли в стадію |

Платіж не є виручкою; кошторис не є фактичною виручкою — у дашбордах ці
показники не змішуються в одну колонку.

## Якість даних

`/data-audit` перевіряє: замовлення без клієнта, кошториси без прив'язки,
ліди без телефону, нульові ціни в каталозі, дублікати клієнтів за `phone_norm`,
рахунки без замовлення. Виправлення застосовуються контрольовано з аудитом.
